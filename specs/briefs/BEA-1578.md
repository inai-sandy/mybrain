# BEA-1578 — A worker is told what a check is, so a first build stops fighting the trial

Linear: <https://linear.app/beakn/issue/BEA-1578>

## Why

Every new agent runs once inside a CHECK before going live (BEA-1553): writes held, sends held,
questions auto-answered. But nothing tells Codex those rules, so every first build meets the trial
blind and reacts however the model guessed that day — his YouTube agent's v3 asked for the held
sheet's link 1,610 times and then failed the check. The versions piling up on every new agent are
not fixing the job; they are groping toward how the check behaves. Tell the model the rules of the
room it is tested in, and the first version passes more often.

## Where

- `api/src/worker/brief-rules.ts` — the shared rules home (BEA-1544 pattern: written ONCE,
  imported). Add `TRIAL_RULE`.
- `api/src/worker/build-brief.ts` and `api/src/worker/repair.ts` — both briefs import and carry it
  (the one-rule-one-home test in `one-rule-one-home.spec.ts` should be extended to it).
- The kit's docs `api/src/worker/kit/KIT.md` — the same fact where Codex reads function contracts.

## The rule (sense, not exact prose)

In a check (trial), `writeSheet`/`writeDocument` return `{ trial: true, url: null, id: null }` and
`notify` returns `{ trial: true }`: treat that as DONE — verify nothing about it, ask nobody for a
link or an id, and carry on to `finish`. A real run never returns `trial: true`. Write a test for
the trial shape too.

## Acceptance (WHEN / MUST)

- WHEN a build brief is written, it MUST carry the trial contract, from ONE shared constant in
  `brief-rules.ts` — never written out longhand in either brief (`one-rule-one-home` guards it).
- WHEN a repair brief is written, it MUST carry the same rule.
- WHEN the brief tells Codex what tests to write, it MUST name the trial shape as one of them.
- A recorded-brief test MUST show the rule lands in the rendered brief text.
- MUST NOT change: the trial still holds every write and reaches nobody; the BEA-1571 repeat-ask
  cap stays as the backstop; promoted workers are untouched (the rule reaches them at next build).

## Traps

- The one-rule-one-home spec matches flattened prose across every non-spec `.ts` file — a copy of
  the sentence in a comment elsewhere will trip it; reference the rule, do not quote it.
- `KIT.md` is copied into every build folder (`dist/worker/kit` via the Dockerfile) — check the
  copy step carries the edit.
