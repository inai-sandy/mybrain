# BEA-1582 — a model hiccup is retried like a vendor hiccup

Linear: <https://linear.app/beakn/issue/BEA-1582>
Ships after BEA-1580 (uses its plumbing classification for the final message). Independent of 1581.

## Why

2026-08-29 17:36, live: the Daily Email Agent's run died with *"the worker-think model returned
nothing"* — one transient blank at OpenRouter (probed fine minutes later). BEA-1496 already decided
this class for vendors: *"a flaky vendor is not a failed run"* — retried at the one call site. A
MODEL call has no such retry, so one provider blink failed the run AND queued a self-repair against
a worker that was never broken: a Codex session spent, a promotion (v10) with no parity baseline,
all for weather.

## Where

- `api/src/llm/llm.service.ts` — the retry lives at the ONE place helper calls resolve
  (`completeHelper` / the shared door under it), for calls made inside a RUN. 2–3 tries, short
  backoff, on: empty/blank answer, 429, 5xx, network. SAME model every try — never a fallback model
  (the owner's no-cheaper-models rule; BEA-1248's null-not-general-model stays for the final
  verdict). Interactive callers (builder chat, chat-edit — a person is waiting) keep failing fast:
  gate the retry on an option or on the helper key set, whichever is cleaner, but decided in ONE
  place, not per caller.
- `api/src/worker/worker-repair.service.ts` (or where `onRunFailed` classifies the cause) — a run
  that failed with the model-blank class MUST NOT enter the repair queue as a `crash`: a model
  outage repairs nothing. Use BEA-1580's classifier to tell them apart — never a second list.
- The final failure message, when retries also blank, is plumbing-class via BEA-1580: calm words,
  honest sentence stored.

## Acceptance (WHEN / MUST)

- WHEN a run-side helper call blanks transiently and a retry answers, the run continues and nothing
  is logged as a failure (a `↻ retried` info line is fine, matching BEA-1496's pattern).
- WHEN all retries blank, the run fails with the plumbing-class message, and NO repair is queued
  for it.
- WHEN a real worker crash happens (exit 1, thrown error in the program), repair queues exactly as
  today — locked by the existing tests.
- Locking tests: transient-then-success; all-blank → plumbing message + no repair row; interactive
  helper still fails fast without retry delay.
- MUST NOT: fall back to a different model; retry inside worker programs or per-caller
  (`NO_PRIVATE_CLOCK_RULE`); change BEA-1248's registry behaviour; add global sleeps to specs (use
  fake timers or a 0-backoff test hook).

## Traps

- The engine (Codex) road has its own budget/messages — this issue is about HELPER calls
  (`completeHelper`); do not touch the engine path.
- `agent-calls-follow-a-named-model.spec.ts` enforces named helpers — keep it green.
- Retry timing in tests: expose the backoff as an injectable/openable constant so the suite never
  actually sleeps.
