# BEA-1624 — voice cleanup + EMO router on openai/gpt-5.6-terra, as settings

Linear: <https://linear.app/beakn/issue/BEA-1624>
Independent. One issue, ship.sh flow.

## Why

Owner (2026-09-05): "why are we using Claude Haiku?" → "use gpt-5.6-terra". Verified on OpenRouter:
`openai/gpt-5.6-terra` (1,050,000 ctx, $2/M in, $12/M out).

Two places still ran on a hardcoded Haiku:
- dictation cleanup — `api/src/voice/voice.service.ts` `clean()` called
  `completeWith({ provider:'openrouter', model:'anthropic/claude-haiku-4.5' }, …, 'voice-cleanup')` —
  no setting, no picker, no way to change it from Settings;
- the EMO router — `emo-router.service.ts` read `emo.router.model` itself and fell back to Haiku, and
  `emo-settings.service.ts` showed Haiku as the default; the picker list `EMO_MODELS` did not offer terra.

## What to build

1. **The named-helper road carries both.** `LlmService.HELPERS` gains `'voice-cleanup'` and
   `'emo-router'`, both defaulting to `openai/gpt-5.6-terra` on OpenRouter. Their Setting rows are the
   owner-facing keys, not `helper.<key>.llm`: a small `HELPER_SETTING_KEYS` map
   (`voice-cleanup` → `voice.cleanup.model`, `emo-router` → `emo.router.model`) that BOTH
   `helperModel()` and `setHelperModel()` read, so the EMO screen, the Voice screen and
   `PUT /api/llm-config/helper/<key>` all write the same row. Both keys are INTERACTIVE (a person or a
   device is waiting) — zero retries, exactly the one-call behaviour they had.
2. **Voice cleanup reads it.** `clean()` → `completeHelper('voice-cleanup', …, 'voice-cleanup')`.
   `config()` answers `cleanupModel` + `cleanupModels`; `PUT /api/voice/cleanup-model {model}` saves
   (only a model from the curated list; `''` = back to the default). Settings → Voice input gets a
   "Cleanup model" select under the "Clean up my dictation" switch.
3. **EMO router reads it.** `route()` → `completeHelper('emo-router', …, 'emo-router')`; the private
   `routerModel()` reader is gone (one reader, in `LlmService`). `EMO_MODELS` = the curated list in
   `api/src/llm/curated-models.ts` (Sonnet 5, Sonnet 4.6, Haiku 4.5, GPT-5.6 Terra, GPT-5, GPT-4o);
   the EMO settings default for the router is read off `HELPERS['emo-router']` so the two cannot
   drift.
4. **Pricing** — `usage/pricing.ts` gets a terra row ($2 / $12) before the broad `gpt-5` row.
5. **Untouched, on purpose:** Talk (`emo.talk.model`, Haiku default), Ask summary + offer, and every
   internal helper (`deep-research-plan`, `review-read`, `radar-translate`, `report-summary`,
   `news-categorise`, `news-flag`, `flow-decompose`, `suggest-evals`, `agent-learn`) stay where they are.

## Locking tests

- default resolves to terra for both keys (no row);
- a changed setting is honoured (voice: `setHelperModel` → `voice.cleanup.model`; EMO:
  `EmoSettingsService.set({routerModel})` → the same row `helperModel('emo-router')` reads);
- a blank / junk / model-less row falls back to the DEFAULT — asserted never Haiku;
- the usage log names the model that ran (`feature:'voice-cleanup'`, `model:'openai/gpt-5.6-terra'`);
- source guard: neither service names a model id inline any more;
- the voice setter refuses a model outside the curated list; `EMO_MODELS` offers terra.
