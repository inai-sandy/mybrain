# BEA-1385 — the UI gate refuses to pass a route it never actually saw

Linear: <https://linear.app/beakn/issue/BEA-1385>

## Why

A ship ran with `UI_ROUTES="/agents"`; the real route is `/agent`. The SPA served its fallback for
the unknown path, the page rendered cleanly, and the gate PASSED — on the wrong screen. Same family
as the expired-login trap: the gate must refuse to bless what it did not actually look at. Every
ship in tonight's batch leans on this gate, which is why it goes first.

## Where

- `.claude/checks/uicheck.sh` only. No app code.

## Acceptance (WHEN / MUST)

- WHEN `UI_ROUTES` names a path that is not a real route, the gate MUST fail with a message naming
  the near-miss ("route /agents does not exist — did you mean /agent?"), never pass on the SPA
  fallback. Route truth = the `Route path=` entries greppable from `web/src/App.tsx` at gate time.
- WHEN the app redirects to the login screen, the gate MUST still report LOGIN WALL (unchanged).
- Parameterised routes MUST still pass (`/agent/a/<real-id>`, `/documents/<id>`): match the route
  table by segment pattern, not literal string.
- A deliberate check proves both directions: `/agents` fails with the near-miss message; `/agent`
  passes.

## Traps

- The gate runs inside ship.sh with `set -e` semantics — a helper that exits non-zero for its own
  reasons kills the whole gate; probe in the same defensive style the login-wall check uses.
- `location.pathname` after redirects: the app rewrites some entries (e.g. `?created=1` flows);
  compare prefixes, not equality.
