# BEA-1622 — denoise device audio before transcription (/emo/device/turn)

Linear: <https://linear.app/beakn/issue/BEA-1622>
Independent. Server half of the pendant noise plan (device half: `emo-fw-src/boards/pendant/design/mic-frontend-plan.md` §6).

## Why

Owner (2026-09-05): pendant clips are hissy and transcribe badly ("25 s → a few words"). The device plan
does stationary hiss + level + quiet pauses on the pendant and tags those uploads `fe=ns1agc`; the server
was to do the rest — a noise-reduction pass before the transcriber, gated so clean audio is never touched,
with a per-turn log line and a locking fixture test.

## What was measured BEFORE building (the part that decides everything)

Ruler: the owner's own kept recordings (`/app/data/emo/recordings/turn-*.wav`, the exact bytes the device
path transcribes) and a synthetic clip (the app's own TTS, 72 words, 19 s) with white hiss mixed at 14 dB
and 8 dB SNR plus an AGC-"pumped" hiss (louder in the pauses, the pendant's shape). Transcriber: **Deepgram
nova-3 through the live app, dictation cleanup OFF** — the same engine `/emo/device/turn` uses. Eight
denoise variants: own STFT Wiener at 8/12/18 dB max attenuation, RNNoise (wasm, hand-instantiated) pure and
60 % blend, ffmpeg `afftdn`, ffmpeg `arnndn` (RNNoise `sh.rnnn` model) pure and `mix=0.6`. Every variant
also had an 80 Hz high-pass.

Owner's hissy clip (`turn-1788586263469.wav`, 22 s, pause floor −41 dBFS, speech −25 dBFS → **16 dB SNR**):

| variant | words (Deepgram) |
|---|---|
| original | **31** |
| Wiener 8 / 12 / 18 dB | 30 / 28 / 22 |
| RNNoise blend 60 % / pure | 21 / 15 |
| afftdn | 28 |
| arnndn pure | 22 — and it hallucinated a list of Telugu names |
| arnndn mix 0.6 | 35 — the extra words ("telecom", "famous") are invented |

Owner's clearer clips (`…506285648`, 17 words; `…490135522`, 55 words): every variant 14–18 / 54–58 words —
no gain, RNNoise pure loses 3.

Synthetic (word accuracy vs the known text): clean 93 %; +hiss 14 dB SNR **93 % before, 92–93 % after every
variant**; +hiss 8 dB SNR 90 % before, 88–92 % after; pumped 14 dB 92 % before, 90–92 % after.

**Verdict:** Deepgram nova-3 is already robust to stationary hiss; a server denoise pass raises the word
count on NO fixture and lowers it on the owner's real clip. His bad clip is not "hiss on top of good
speech" — the speech itself sits only 16 dB above the floor, and no filter brings back what the mic did not
capture. The fix is on the device (mic gain / the pumping normaliser), exactly as the pendant plan says in
§1.2. Building the pass "on" would break the issue's own rule "never worsen clean audio".

## Guardrail — the owner's goal

Every EMO device (Agent/Watch/Capsule/Pendant) shares `/emo/device/turn`. Nothing here may change what
reaches the transcriber for an untagged take, may not downgrade the transcription model (Deepgram nova-3
via `transcribeWith('deepgram', …)` stays), and may not add a heavy dependency (the api image has no
ffmpeg; an Alpine ffmpeg is ~100 packages). No user-facing pipeline change = no UI.

## What to build (the honest, useful half)

1. **The ruler, on every device turn.** `api/src/emo/emo-audio-stats.ts` (pure): 20 ms frame RMS →
   `floorDbfs` (10th percentile — the pause floor), `speechDbfs` (90th), `snrDb`, `seconds`; `wordCount`;
   `denoiseLine()` → the log line the issue asked for, printed after transcription in BOTH roads
   (`processPending` and `turnInner`):
   `[emo] denoise: floor -41.0 dBFS → -41.0, applied no (server pass off: measured no gain, BEA-1622), speech -25.0 dBFS, snr 16 dB, 22.4s, fe none, words 31`.
2. **The `fe` hand-shake.** `POST /emo/device/turn?…&fe=ns1agc`: the tag rides on `opts.fe`, into the
   pending filename (`-fe_<tag>`, `[a-z0-9]{1,16}` only) and into the log line; a tagged take SKIPS
   `normalizePcm` (the plan's "no second AGC — the device's level is already right"). Untagged takes are
   byte-for-byte as today.
3. **Fixtures kept** under `api/src/emo/fixtures/denoise/`: `clean-16k.wav` (the TTS clip; the spec mixes
   hiss at 14 dB SNR with a fixed-seed PRNG — nothing noisy is stored) and `pendant-hiss-2026-09-05.wav`
   (the owner's clip above, his ask: "keep the sample as a fixture").
4. **Locking specs**: the ruler on the clean clip (floor < −55 dBFS, SNR > 35 dB), on clean+hiss 14 dB
   (floor ≈ −34 dBFS, SNR 14–22 dB — the ruler reads the SNR that was mixed in), on the owner's clip
   (floor −41 ± 2 dBFS, SNR < 20 — "buried", not "hissy but clear"); the line format; `fe=ns1agc`
   skips the normaliser and survives the pending filename; the line is printed with the word count.
5. **CLAUDE.md** project section: five lines on the ruler, the tag, and the measured verdict.

## What is NOT built, and why — PARKED for the owner

The noise-reduction pass itself (and its Settings toggle/threshold). Measured on the owner's sample and
on synthetic hiss, it never raises the word count and it lowers it on his clip; shipping it OFF would be
dead code with a switch that makes transcripts worse. It comes back only if a REAL sample shows the case
the filters are for: speech clearly above the floor (SNR ≥ 20 dB) with loud non-stationary room noise
(fan, traffic, dishes). The ruler shipped here prints exactly those numbers for every take, so the next
bad clip carries its own diagnosis.

## Acceptance (WHEN / MUST)

- WHEN any device turn is transcribed, the server MUST print one `[emo] denoise:` line with floor,
  applied yes/no + reason, SNR, seconds, fe tag and word count.
- WHEN `fe=ns1agc` is on the upload, `normalizePcm` MUST NOT run and the tag MUST appear in the line; WHEN
  it is absent, the bytes reaching the transcriber MUST be identical to today's.
- The transcription model MUST NOT change anywhere (`transcribeWith('deepgram', …)` / `transcribeMeeting`).
- Specs above green; `api` + `web` suites green; `tsc --noEmit` clean in `api/`.
- No new npm dependency, no image change.

## Traps

- `EmoDeviceService`'s constructor is positional in many specs — add nothing to it.
- The pending filename regex is the job description; the new `-fe_` token must sit BEFORE `-ans_` and stay
  optional, or every pre-1622 pending file is skipped by the sweep.
- `/api/voice/config`'s engine is cached ~60 s server-side — a measurement that flips the engine must wait
  before trusting the next call (found while measuring; the owner's settings were restored to
  `openai` + cleanup on).
- UI_ROUTES="-" — no screen changes.
