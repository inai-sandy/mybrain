# BEA-1577 — A repair attempt only counts when Codex actually tried

Linear: <https://linear.app/beakn/issue/BEA-1577>

## Why

Self-repair exists so a broken worker fixes itself with no owner in the loop. On 2026-08-28 it
paused a job after "2 failed repairs" in which **Codex was never asked anything**: both attempts
were the runner refusing `/build` with *"This job is busy here (run)"* (the runner's own live-map,
after the app-side job lock had already been claimed). Twice more, the evidence file
`samples/failing.json` was built at ~2.04MB — over the runner's own 2,000,000-byte body cap — and
that refusal also counted. The owner was told his agent could not be fixed when nothing was tried.
This is the exact "customer cannot fix this" failure blocking the sale.

## Where

- `api/src/worker/worker-repair.service.ts` — `attempt()` records the build outcome; `COUNTED`,
  `triedFor()`, `MAX_ATTEMPTS`; the queue row lifecycle (`finish`, `nextRow`).
- `api/src/worker/worker-runner.client.ts` — the `notStarted` flag already distinguishes "refused
  before any spawn" (BEA-1394); `/build` refusals need the same fact carried.
- `services/host/worker-runner.server.js` — `/build` answers for busy / oversized / kit-refused;
  make sure each is tellable from a Codex session that ran and failed. Repo copy is the truth;
  install to `/home/sandy/worker-runner/server.js` and bounce the process (systemd `Restart=always`
  brings it back — NEVER add a second supervisor).
- Evidence building: where `samples/failing.json` is assembled from `ToolSample` rows.

## Acceptance (WHEN / MUST)

- WHEN the runner refuses a repair before any Codex session starts (busy, oversized body, kit
  refused, unreachable), the attempt MUST NOT count toward `MAX_ATTEMPTS`: the `WorkerBuild` row is
  closed with a status outside `COUNTED` (or requeued), and the queued cause stays queued for the
  next tick.
- WHEN the failing evidence would exceed the runner's body cap, it MUST be trimmed to fit BEFORE
  sending — cap per-answer payloads, keep the newest, and note inside the file that it was trimmed.
  A repair with trimmed evidence is better than no repair.
- WHEN two REAL Codex attempts fail (tests red, parity held → declined, could-not-produce-rows),
  the job MUST still pause exactly as today, with the same owner message.
- The busy case MUST be reproduced in a test: app lock claimable, runner answering busy — the
  attempt is not counted and the cause is retried on a later tick.
- MUST NOT change: `MAX_ATTEMPTS = 2`; the parity guard; `deleteAgent`'s sweep of repair rows.

## Traps

- The cap's counter and the "already tried" note read the SAME statuses (`COUNTED`) — a new
  plumbing status must be invisible to both, or the two lists drift (this bit BEA-1393 in review).
- `repair()` already returns `'busy'` when the APP lock is held — the gap is the RUNNER saying busy
  after that lock was claimed. Do not "fix" the app-lock path; it is correct.
- The runner's `/build` body cap is defined in the runner; read the constant, never restate the
  number in the app (one rule, one home).
