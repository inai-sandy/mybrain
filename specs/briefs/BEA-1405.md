# BEA-1405 — Brief First 1/6: the brief model, and the interview that writes it

Part one of **Brief First** — replacing the 8-box agent form with a brief the owner reads and approves.
Plan: <https://claude.ai/code/artifact/5c17fc65-a717-43b3-9bc6-4221968b0d94>
Linear: <https://linear.app/beakn/issue/BEA-1405>

Server side only. The screen is 2/6 (BEA-1406).

## Why

`AgentPlan` (`api/src/social/plan.ts`) has eight boxes: sources (max 11 pages) · creators · merge ·
shape (one sentence) · watch · output (sheet|document) · notify (booleans) · schedule. **`notify` has
no message text**, so "WhatsApp me a summary grouped into work/personal/finance" cannot be expressed —
the agent could only ever send "finished · N rows". The builder promised the owner that format in
chat, the form silently dropped it, and nobody compared the two. Same failure shape for "read all my
emails" (no box for how many) and for anything that is not the fixed line
fetch → merge → shape → save → notify.

## Build

**`AgentBrief`** — one row per version, per `AgentArea`:
`id · areaId · version · status(draft|approved) · sections Json · transcript Json · approvedAt ·
createdAt · updatedAt`.

`sections` is an ordered list of seven fixed keys, each holding **free-text lines**:
`want · sources · filter · output · when · success · trouble` — plus `killed`.
Every line is `{ text, origin: 'owner'|'tool'|'ai', struck: boolean, sampleId?: string }`.

- `origin:'owner'` — the owner's own words, quoted verbatim, never reworded.
- `origin:'tool'` — a statement backed by a real call; MUST carry the `ToolSample` id that proves it.
- `origin:'ai'` — the builder's own suggestion. This is the tag that has to be visible.

`transcript` is the **whole conversation**, in order, every turn, nothing summarised. A line the owner
strikes out is **marked struck, never deleted** (both in `sections.killed` and in the transcript turn
it came from).

**The interview rules, enforced in code, not in the prompt:**

1. **Look before you plan.** A `sources` line may only be `origin:'tool'` if a real `ToolSample`
   backs it. The builder gets a `look(actionId, args)` step that makes one real call through the
   existing `BuilderSampleService` (≤3 calls / ≤5 credits stays).
2. **`approve()` refuses** a brief where: any source has no real look · `output` asks for a message
   but the exact message text is missing · `success` is empty · `want` has no `origin:'owner'` line.
3. Refusals are **plain English**, naming the missing thing ("I haven't looked at Gmail yet" /
   "You haven't told me what the WhatsApp should say").
4. The builder's answer-length limit must not silently truncate a brief: on overrun, say so honestly
   and re-ask once — never fall through to a generic "I couldn't work that out". (BEA-1404 evidence:
   two turns at exactly 8,000 completion tokens, answer cut mid-JSON, salvage failed, fell to
   `cantDo` at `agent-areas.service.ts:348`.)

**`BriefService`**: `draft()` `update()` `strike()` `approve()` `latest(areaId)` `forCodex(areaId)`.
`forCodex()` returns `{ brief, transcript }` — the transcript with strike-outs marked, and the brief
on top. **Where they disagree, the brief wins** — state that in the payload itself, in words.

**Nothing is removed.** `AgentPlan`, `runPlan()` and the nine live agents keep working exactly as they
do. This adds a road; it does not close one.

## Acceptance (WHEN / MUST)

- WHEN a brief is approved with a source that was never sampled, approve MUST refuse and name the
  source in plain English.
- WHEN a brief asks for a WhatsApp message and the message text is empty, approve MUST refuse.
- WHEN `success` is empty, approve MUST refuse.
- WHEN the owner strikes a line, it MUST still be present, marked struck, in both `sections.killed`
  and `transcript`.
- WHEN `forCodex()` is called, the transcript MUST contain every turn of the conversation and every
  struck line MUST be marked.
- WHEN a `tool`-tagged line is written, it MUST carry a `ToolSample` id that exists.
- WHEN the builder's answer overruns its token ceiling, the owner MUST get an honest message saying
  so, and the turn MUST be re-asked once — never `cantDo`.
- Existing behaviour MUST be untouched: the nine live agents, `planFromAgent()`, `runPlan()` and their
  tests all stay green.
