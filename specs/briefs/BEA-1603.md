# BEA-1603 — Agent on/off: a goal-built agent can never be left stuck off

Linear: <https://linear.app/beakn/issue/BEA-1603>
Independent. Ships first in this batch (BEA-1604 follows; both touch goal-trial.service.ts and agent.service.ts — sequential, never in parallel).

## Why

Owner, 2026-09-03: the Daily Email Agent was set to "every day at 23:00" and never ran. Live: scheduler is fine (the Instagram digest fired at 08:00 IST on 31 Aug); the agent has `enabled=false`, `pausedReason=null`, `lastFiredKey=null`. It was NEVER switched on: goal-born agents are created off (`api/src/worker/goal-trial.service.ts` `jobFor()` — `enabled:false` "off until he keeps it"); the only on-switch is the "Keep it" answer in `onAnswer()`; that question is asked only `if (ok)` after the FIRST trial run in `work()`. Its first run failed (Notion) → never asked → nothing asks again. Manual runs ignore the switch (only the clock checks it), so it looked alive. 4 of 7 goal agents are off this way.

The screen hid it: `web/src/pages/AgentApp.tsx` draws the schedule line + "next: today 23:00" regardless of `enabled` (~L483); the pause banner needs `pausedReason` (~L503); there is NO on/off control anywhere except the bulk bar Pause/Resume on the Agents board (`Agents.tsx` ~L1738/1743, only when agents are ticked). `toggleSaved()` (`Agents.tsx` ~L1006) exists but nothing renders it. `AgentAreaPage.tsx` ~L290 shows a grey "paused" pill.

## What to build

1. **Schedule means on.** In `AgentService.updateAgent()` (`api/src/agent/agent.service.ts` ~L723): when a non-null `schedule` is saved and the agent is off with NO `pausedReason`, also set `enabled:true`. A system pause (`pausedReason` set) is NOT overridden. The page toast reads "Saved and switched on — Every day at 23:00" (the PATCH answer carries `enabled`; `AgentApp.tsx` ~L920 reads it for the toast).
2. **"Keep it" can never leave an agent stuck.** Ask the keep question after the first run of a goal agent that finishes `done` — whenever that happens, manual or scheduled — not only the first trial run. Ask once; never if the agent is already `enabled`; never twice for one agent (an open or answered keep waitpoint for that agent = asked). Implement as a hook on the run-finished path (`AgentService.finishRun()` already has `setRunFailedHook`; add the matching done-hook seam, registered by `GoalTrialService` at boot like the failed hook) that calls the EXISTING `askHim()` unchanged. `work()` stays as it is (it still asks after a green trial run; the hook must not double-ask — the "asked once" guard covers both). Do not add a second trial flow.
3. **A switch on the agent page.** `AgentApp.tsx` header: an On/Off toggle next to the name — reuse the shared toggle from `web/src/ui/` (grep for the switch used by "Keep adding to one sheet" / `agentJobFields.tsx`; do not invent one). Off: the schedule line becomes "Off — it will not run on its own. Would run every day at 23:00." (or "Off — it will not run on its own." with no schedule). On: unchanged. The system-pause banner stays exactly as it is. PATCH `{ enabled }` through the existing route; toast "Switched on" / "Switched off".
4. **Honest words on the board, nothing else on the board changes.** `AgentAreaPage.tsx` ~L290: pill "paused" → "off" (system pause keeps "paused itself"). Bulk bar `Agents.tsx` ~L1738/1743: "Pause"/"Resume" → "Switch off"/"Switch on" (toast wording to match). No layout change, no behaviour change on the board.
5. **Data step on ship.** One idempotent migration/startup pass: `enabled=true` for every agent that is off, has `pausedReason IS NULL`, and has a non-null `schedule`. Today that is exactly the Daily Email Agent (`ec3d5ac7…`). The other three off goal agents stay off.

## Acceptance (WHEN / MUST)

- WHEN a schedule is saved on an off agent with no pausedReason, it MUST become enabled and the toast MUST say "Saved and switched on — …".
- WHEN a schedule is saved on a system-paused agent, it MUST stay paused (`enabled:false`, reason kept).
- WHEN a goal agent's first run fails and a later run finishes done, the "Keep it / Send it back" question MUST be asked exactly once; WHEN the agent is already on, it MUST NOT be asked; WHEN the trial run itself was green, it MUST be asked once (not twice).
- WHEN an agent is off, the agent page MUST show the switch Off and the "Off — … would run …" line; WHEN on, the schedule line reads exactly as today.
- WHEN this ships, the Daily Email Agent MUST be enabled (verify live: `enabled=1`) and the other three off goal agents MUST still be off.
- MUST NOT change: goal creation, `jobFor()`'s born-off default, `work()`, `startRun()/startOnRoad()`, `matches()`, any run road. `agent-scheduler.service.spec.ts` (Monday 08:00 IST case) MUST stay green untouched.
- Locking tests for every line above. UI routes for the gate: `/agent/a/ec3d5ac7-713e-471f-be3a-05faf63b40c1 /agent` (SPACE-separated in UI_ROUTES).
