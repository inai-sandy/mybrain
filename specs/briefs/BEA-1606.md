# BEA-1606 — Agent Settings sheet: an instant-save control must not wipe an unsaved source edit

Linear: <https://linear.app/beakn/issue/BEA-1606>
Independent, web-only. Ships last in this batch.

## Why

In `web/src/pages/AgentApp.tsx`: editing a source's arguments sets `sourcesDirty` and mutates local `a.toolArgs` (~L759), waiting for the sticky "Save changes" bar (`saveAll` ~L353-367). Any instant-save control — WhatsApp toggle (~L800), output destination (~L791), sheet id (~L793), schedule (~L920), skills (~L957), tools (~L991), keep history (~L1016), model (~L1008) — calls `patch()`, which does `setA(d)` with the server's copy (~L377) and silently discards the unsaved source edits while `sourcesDirty` stays true. The bar then PATCHes the server's own `toolArgs` back (a no-op) and toasts "Saved". Task/rubric drafts are safe (`dirtyRef` guard ~L229); only the sources draft leaks.

## What to build

1. `patch()` merges instead of replacing: while `sourcesDirty` is true, keep the local `toolArgs`/`tools` over the server copy — the same idea as `load()`'s `dirtyRef` guard for task/rubric. ONE helper used by every instant-save call site, not a per-control fix.
2. While any section is dirty, the sticky bar names it ("Sources not saved yet") so the state is visible.
3. If an instant-save would still have to drop a draft, block it with "Save your source changes first" rather than lose them (only if (1) cannot cover a case).
