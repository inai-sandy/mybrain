# BEA-1403 — Gmail agents silently read ONE email; the plan runner gets the loud check

Linear: <https://linear.app/beakn/issue/BEA-1403> (Urgent — the full evidence table is there)

## Why

"Nightly Important Email Summary" ran twice, reported done, WhatsApped him — and had read **one
email**. `svc:gmail.fetch_emails` with no `max_results` returns exactly 1 message, and the plan
runner has no "is this obviously wrong" check: contracts (`kit.expect`, the BEA-1377 tripwire)
exist only on the worker road, while agents on the plan road can still report a 1-email day as
success. The lesson was written into the new road and left out of the old one.

## Where

- `api/src/tools/knowledge-notes.ts` — the trap note for `svc:gmail.fetch_emails` (default = 1);
  sweep sibling actions for the same silent-default shape (`max_results`, `limit`, `page_size`).
- Builder rules (`thinking-builder.ts` facts / `RULES_TEXT`): a planned Gmail fetch MUST carry an
  explicit `max_results`; page beyond it when the owner asks for "all".
- `api/src/social/social-agent-run.service.ts` (`runPlan`) + `api/src/worker/contract.ts` — REUSE
  `contractFromPlan()`; do not write a second contract.

## Acceptance (WHEN / MUST)

- WHEN a Gmail source is planned, `max_results` MUST be set explicitly, and the fact card MUST
  state that the vendor default is 1.
- WHEN a plan-runner fetch returns 1 item where this job's own `ToolCall` history shows many, the
  run MUST say so loudly — and the owner's WhatsApp MUST carry the doubt, never a false all-clear.
- WHEN shaping keeps 0 rows out of a non-empty fetch on the plan runner, the run MUST fail with the
  BEA-1377 wording ("fetched N answers but recognised 0 rows — this is a My Brain bug…").
- Locking tests use this agent's REAL recorded arguments and answers (they are in the issue).
- MUST NOT change: the worker road's contracts; Gmail's 21:00/23:30 windows and daily cap.

## Traps

- The history comparison must read the job's OWN `ToolCall` rows, not a global average.
- A genuinely quiet inbox is not a failure — the loud path is for 1-out-of-many against history,
  and for 0-shaped-from-non-empty; never for a genuinely empty day (the BEA-1359 rule: honest
  empties finish done).
