# BEA-1604 — "Keep it" saves a double-encoded schedule the clock can never match

Linear: <https://linear.app/beakn/issue/BEA-1604>
Ships after BEA-1603 (same files). Independent otherwise.

## Why

`GoalTrialService.onAnswer()` → `scheduleFor()` → `readSchedule()` in `api/src/agent/goal.ts` (~L387-399) returns the schedule already `JSON.stringify`'d. It is passed to `updateAgent({ schedule: when.schedule })`; `agent.service.ts` ~L723 stringifies AGAIN. The DB holds `"{\"every\":\"day\",\"at\":\"22:00\"}"` (a quoted string). `shapeAgent()` parses once → a string → `AgentScheduler.matches()` (~L46) hits `!s.every` → never fires. `web/src/ui/SchedulePicker.tsx` ~L47 does `'event' in value` on a string → TypeError, the Settings row crashes. Introduced by 895a943 (BEA-1482). `api/src/worker/goal-trial.spec.ts` ~L293 stubs `updateAgent` and asserts the raw patch, so it passes with the bug live. The Daily Email Agent escaped only because the owner re-set the time from the UI.

## What to build

1. `readSchedule()` returns `{ schedule: { every, at?, dow? } | null, text }` — an OBJECT. `onAnswer()` passes it through unchanged. `updateAgent()` keeps stringifying once. One shape, decided in one place; the `schedulePrompt` and Codex call are untouched.
2. Defensive read in ONE place (`AgentService.parse`/`shapeAgent()` or a tiny `readStoredSchedule()` used by both `shapeAgent` and `listSchedulable`): a stored value that parses to a string is parsed once more; log a warning naming the agent. Heals rows already written.
3. `SchedulePicker` guards a non-object value: renders the "manual" state, never throws.
4. Optional one-off startup pass rewriting double-encoded rows in place (idempotent) — only if simpler than (2); (2) is required either way.

## Acceptance (WHEN / MUST)

- WHEN "Keep it" is answered on a goal naming "every day at 22:00", the stored `schedule` column MUST start with `{` and `shapeAgent().schedule.every` MUST be `"day"`.
- WHEN a row already holds a double-encoded schedule, `matches()` MUST still fire it at its time and the Settings sheet MUST not crash.
- Locking tests: `goal-trial.spec.ts` rewritten so the keep case runs the REAL `AgentService.updateAgent()` against a prisma stub that records `data.schedule` (no stubbed updateAgent for that case); `goal.spec.ts` asserts an object; `agent-scheduler.service.spec.ts` gains a double-encoded-row case; `SchedulePicker.test.tsx` gains a string-value case.
- MUST NOT change the trial flow, `work()`, the scheduler's timing, or any run road.
